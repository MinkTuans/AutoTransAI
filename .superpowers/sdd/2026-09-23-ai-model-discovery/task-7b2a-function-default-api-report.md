# Task 7B2A — canonical Function default write

Base `ac500ff`; implementation commit `b1f024d`. Implementation: `PUT /api/ai/functions/{function_id}` in a separate safe-write router. Body accepts only `model_id`, an exact `CatalogModel.id`; it derives and persists the provider ID from that row. It rejects unknown function/model, retired or disabled model/provider, incompatible capability, and unavailable key/access. Fully unknown capability remains selectable. Credential-scoped models require an enabled key and listing edge; Fal/ElevenLabs public-catalog candidates require an enabled provider key without claiming per-key entitlement; Edge TTS and system Pollinations/local-image use the existing router's keyless allowance. The result uses the canonical GET `FunctionView` shape and clears prior `configuration_error` while preserving legacy fallback columns.

Concurrency: review found the original plain model/config SELECTs could establish a MySQL REPEATABLE READ snapshot before the provider lock; later plain reads could stay stale. The provider-ID preflight now closes its session before the write transaction. The write transaction first takes the shared provider `catalog_revision` lock, then uses current `FOR UPDATE` reads for function, model, provider, and key/access. Refresh and credential writers use the same provider lock, so a concurrent retirement or key change serializes against the selection; an in-flight older refresh becomes stale. Tests commit retirement, model/provider disable, and key disable before lock acquisition and verify 409 with the previous config preserved. A query-capture test compiles the executed locking reads with the MySQL dialect and asserts `FOR UPDATE` on model, provider, and key/access. No live MySQL server was used.
