## Review fix — capability-specific keyless eligibility

The original picker inferred eligibility from `access_scope === keyless`, but the unfiltered catalog scope meant keyless for *any* capability. A fully unknown Pollinations/local-image system row therefore appeared selectable for STT even though canonical PUT correctly rejected it. Capability-filtered `/api/ai/models` rows now compute `selectable` with the same current provider/model, capability, and credential/keyless access rule as PUT, and compute `access_scope` for that requested capability. Unfiltered catalog list and detail keep their provider-wide scope and return `selectable: null`; the Models tab is unchanged. The picker enables Select only for explicit `selectable === true`, failing closed on missing/older DTOs, and PUT remains final authority if state changes after listing.
