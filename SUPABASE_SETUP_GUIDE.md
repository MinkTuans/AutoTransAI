# SUPABASE PROJECT SETUP & CONFIGURATION GUIDE

This guide details the exact steps required to configure your Supabase Project for AutoTransAI.

---

## 1. Create Supabase Project
1. Log in to [Supabase Dashboard](https://database.new) and click **New Project**.
2. Select your Organization, enter a **Project Name** (e.g. `AutoTransAI`), set a secure **Database Password**, and choose your preferred Region.
3. Once provisioned, navigate to **Project Settings ➔ API** to retrieve your credentials.

---

## 2. Environment Variables Configuration

Copy the following values into your root `.env` file:

```env
# ============================================================
# Supabase Configuration
# ============================================================
SUPABASE_URL=https://<your-project-ref>.supabase.co
SUPABASE_ANON_KEY=<your-anon-key>

# Backend Only - NEVER expose SERVICE_ROLE_KEY to frontend
SUPABASE_SERVICE_ROLE_KEY=<your-service-role-key>

# PostgreSQL Database Connection URL (Async Engine)
DATABASE_URL=postgresql+asyncpg://postgres:<your-db-password>@db.<your-project-ref>.supabase.co:5432/postgres

# Supabase Storage Buckets
SUPABASE_STORAGE_BUCKET_PRIVATE=autotransai-private
SUPABASE_STORAGE_BUCKET_PUBLIC=autotransai-public
```

> [!CAUTION]
> **SECURITY MANDATE:** `SUPABASE_SERVICE_ROLE_KEY` has full administrative permissions. It is read strictly by the FastAPI backend in server environment variables and MUST NEVER be exposed to browser clients or committed to git.

---

## 3. Supabase Storage Buckets Setup

AutoTransAI requires two Supabase Storage buckets:

### Bucket 1: `autotransai-private` (Private Storage)
- **Bucket ID / Name:** `autotransai-private`
- **Public Access:** **DISABLED (Private)**
- **Purpose:** Secure storage for user uploaded source videos, extracted WAV audio, TTS segment speech files, intermediate FFmpeg renders, and project drafts.
- **Access Strategy:** Served via temporary **Signed URLs** generated by the backend (`get_signed_url(object_key, expires_in=3600)`).
- **Max File Size:** 2000 MB (2 GB)

### Bucket 2: `autotransai-public` (Public Storage)
- **Bucket ID / Name:** `autotransai-public`
- **Public Access:** **ENABLED (Public)**
- **Purpose:** Public storage for final rendered output videos, channel thumbnails, and exportable social assets.
- **Access Strategy:** Served via direct **Public URLs** (`get_url(object_key, is_public=True)`).
- **Max File Size:** 2000 MB (2 GB)

---

## 4. Storage Path Architecture
Media files are stored in Supabase Storage using structured, project-isolated key paths:

```text
autotransai-private/
├── projects/{project_id}/
│   ├── source/               # Source video clips
│   ├── audio/                # Extracted WAV audio
│   └── tts/                  # Generated TTS WAV clips
└── translator/
    ├── assets/{asset_id}/    # Uploaded/Downloaded source video files
    └── jobs/{job_id}/
        ├── audio/            # Processed PCM audio
        └── tts/              # Time-stretched dubbed segment clips

autotransai-public/
└── translator/
    └── jobs/{job_id}/
        └── final_dubbed_video.mp4  # Final exported video output
```

## 5. SQL Bucket Initialization Script (Optional)

If you have access to the Supabase SQL Editor, run the following SQL script to automatically provision both buckets and policies:

```sql
-- 1. Create Private Bucket
INSERT INTO storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
VALUES ('autotransai-private', 'autotransai-private', false, 2097152000, NULL)
ON CONFLICT (id) DO UPDATE SET public = false;

-- 2. Create Public Bucket
INSERT INTO storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
VALUES ('autotransai-public', 'autotransai-public', true, 2097152000, NULL)
ON CONFLICT (id) DO UPDATE SET public = true;

-- 3. RLS Storage Policy for Public Bucket Read Access
CREATE POLICY "Public Read Access for autotransai-public"
ON storage.objects FOR SELECT
USING (bucket_id = 'autotransai-public');
```
